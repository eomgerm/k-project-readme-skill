# 마크업 골격

한국 부트캠프·동아리 README 16개에서 반복된 마크업이다. 골격만 가져다 쓰고 문구는 새로 쓴다.

## 1. 히어로

배너 이미지 → 가운데정렬 링크줄. 링크줄은 팀이 실제로 쓰는 곳만 넣는다.

```html
<img src="TODO_배너_이미지" alt="{서비스명}" width="100%"/>

<p align="center">
  <a href="{배포주소}">
    <img src="TODO_바로가기_버튼" alt="{서비스명} 바로가기" width="250"/>
  </a>
  <br/><br/>
  <a href="{노션}">팀 노션</a>
  &nbsp;|&nbsp;
  <a href="{위키}">개발 위키</a>
  &nbsp;|&nbsp;
  <a href="{백로그}">백로그</a>
</p>
```

앱 프로젝트는 로고를 왼쪽에 띄우고 제목과 스토어 링크를 붙이는 변형을 쓴다.

```html
# {서비스명} <a href="{앱스토어_링크}"><img src="TODO_앱_로고" align="left" width="100"/></a>
```

## 2. 목차

본문이 8KB를 넘을 때만 넣는다. 앵커는 소문자, 공백은 `-`, 이모지는 제거하고 앞에 `-`가 남는다.

```markdown
- [✍🏻 서비스 소개](#-서비스-소개)
- [🔥 {프로젝트 고유 문구}](#-프로젝트-고유-문구)
  * [{하위 항목}](#하위-항목)
```

## 3. 서비스 소개

한 줄 캐치프레이즈 뒤에 불릿. 개수는 2~5개로, 내용에 따라 다르게.

```markdown
## ✍🏻 서비스 소개

<img src="TODO_소개_이미지" alt="{서비스명} 소개"/>

- {서비스명}은 {한 줄 정의}입니다.
- {특징 하나}
- {특징 둘, 여기는 길게 두 줄로 써도 된다}
```

## 4. 핵심 기능 — GIF 테이블

가장 강한 관용구이고 손으로 짜기 제일 귀찮은 부분이다. 상단 칸에 미디어, 하단 칸에 캡션.

```html
### {기능 묶음 이름}

> {이 묶음을 한 줄로 설명}

<table align="center">
<tr>
  <td><img src="TODO_기능1_GIF" alt="{기능1}"/></td>
  <td><img src="TODO_기능2_GIF" alt="{기능2}"/></td>
</tr>
<tr>
  <td align="center">{기능1 캡션}</td>
  <td align="center">{기능2 캡션}</td>
</tr>
</table>
```

모바일 앱 스크린샷은 3~4열, 웹은 2열이 보기 좋다. `width`는 모바일 280~300, 웹 480~600.

## 5. 기술적 도전 (부트캠프형)

4단 구조. **라벨은 반드시 갈아쓴다** — 원문 라벨을 그대로 쓰면 출처가 드러난다.

```markdown
## 🔥 {프로젝트 고유 문구로 만든 헤딩}

> {이 섹션 전체를 한 줄로}

### [{FE|BE|iOS}] {무엇을 얼마나 개선했는지 수치까지 넣은 제목}

- **{왜 했나}**
    - {마주친 문제. 수치나 증상으로 구체적으로}
- **{뭘 했나}**
    - {시도한 것들. 실패한 시도도 넣으면 훨씬 사람 글이 된다}
- **{어떻게 됐나}**
    - {결과. 전후 수치를 나란히 적는다}
- {더보기 유도 문구는 항목마다 다르게} → [{링크 제목}]({URL})
```

전후 수치가 없으면 이 섹션을 억지로 만들지 않는다. 수치 없는 기술적 도전은 홍보체가 된다.

## 6. 기술 스택

**표를 기본으로 한다.** 뱃지는 최대 12개까지, 넘으면 표로 바꾼다
(실측 최다 27개 — 그 정도면 읽히지 않는다).

```markdown
## 🛠 기술 스택

| 영역 | 사용 기술 |
| --- | --- |
| 언어·빌드 | {...} |
| UI | {...} |
| 상태 관리 | {...} |
| 네트워크 | {...} |
| 데이터베이스 | {...} |
| 인프라·CI/CD | {...} |
| 협업 | {...} |
```

뱃지를 쓸 때의 형식. `for-the-badge`가 한국 README의 사실상 표준이다.

```markdown
![React](https://img.shields.io/badge/React-61DAFB?style=for-the-badge&logo=react&logoColor=white)
```

## 7. 아키텍처 + 폴더 트리

다이어그램 이미지 뒤에 주석 달린 트리. **주석이 핵심이다** — 트리만 있으면 아무 정보가 없다.
헤딩과 설명 문장은 마크다운으로 쓰고, 트리는 `text` 코드블록에 담는다.

~~~
## 🏗 아키텍처

<img src="TODO_아키텍처_다이어그램" alt="시스템 아키텍처"/>

{다이어그램을 두세 문장으로 풀어 설명한다. 왜 이렇게 나눴는지를 쓴다}

```text
├── {디렉터리}          # {무엇을 담당하는지 한국어로}
├── core
│   ├── data            # {...}
│   └── domain          # {...}
└── feature
    └── {기능}          # {...}
```
~~~

## 8. 팀원

아바타 가로 테이블. 파트가 섞이면 헤더에 파트를 적는다.

```markdown
## 👥 팀원

| {파트} | {파트} | {파트} |
| :---: | :---: | :---: |
| <img src="https://avatars.githubusercontent.com/u/{ID}?v=4" width="150"/> | <img src="https://avatars.githubusercontent.com/u/{ID}?v=4" width="150"/> | <img src="https://avatars.githubusercontent.com/u/{ID}?v=4" width="150"/> |
| [{닉네임}](https://github.com/{로그인}) | [{닉네임}](https://github.com/{로그인}) | [{닉네임}](https://github.com/{로그인}) |
| {담당한 것} | {담당한 것} | {담당한 것} |
```

아바타 URL은 `gh api repos/{owner}/{repo}/contributors --jq '.[] | "\(.login) \(.avatar_url)"'` 로 얻는다.
`gh`가 없으면 이름만 채우고 아바타 행은 지운다 — `TODO`로 남기면 깨진 이미지가 줄줄이 뜬다.

## 9. 컨벤션

넣을 거면 실제로 지킨 규칙만 적는다. 안 지키는 규칙을 적으면 저장소가 거짓말을 한다.

```markdown
## 📌 컨벤션

### 브랜치
- `main` / `develop` / `feat-{이슈번호}-{작업명}`

### 커밋
- `{type}: {한국어 본문}`
- `feat` `fix` `refactor` `docs` `chore` `test`
```
